In Kolmena, a job tells an agent to run a task on a schedule, or when something happens in a connected app, and deliver the result to a chat or channel. You can set up one-time, repeating, or event jobs, change them later, and review every run. This page shows you how to create a job, pick a schedule or an app event, manage its state, and resume it after an automatic stop.

## Before you begin

Make sure the agent you want to schedule is [created and published](/agents/create-an-agent). Jobs persist across all published versions of that agent, so updates to the agent do not break existing schedules.

<Note>
  You can have up to 25 active or paused jobs at a time. If you reach the limit, delete an old job before adding a new one.
</Note>

## Draft a job from a description

The fastest way to create a job is to describe it in plain words. Maya drafts the name, task, agent, and trigger, either a schedule or an app event. You review the draft in the job form before you save it. Use this when you know what you want done but don't want to fill in every field yourself.

<Steps>
  <Step title="Open the Describe Job tab">
    On the [Jobs page](https://app.kolmena.ai/jobs) or in an agent's **Configure > Jobs** tab, click **New Job**. The **Describe Job** tab opens.
  </Step>
  <Step title="Describe the job">
    Write what the agent should do and when, then click **Draft The Job**. For example:

    ```text
    Every Monday, flag stalled deals by comparing this week's pipeline to last
    ```

    ```text
    Summarize #design-reviews on Slack and post decisions to the thread
    ```

    Click **Stop** to cancel while Maya is drafting.
  </Step>
  <Step title="Review the draft">
    The form opens with the draft and a **Drafted from your description** banner that names the agent Maya picked. Check the name, task, trigger, and settings, and change anything that is wrong. Click **Edit description** to rewrite your description and draft again.
  </Step>
  <Step title="Save the job">
    Click **Add Job**.
  </Step>
</Steps>

Keep these points in mind:

- If you start the job from an agent's **Jobs** tab, the job always goes to that agent. The agent is shown locked in the draft.
- Maya leaves out any setting she can't confirm, such as an event setting that doesn't match the app's options. Fill those in before you save.
- Name the app in your description, for example "on Slack", so Maya picks the right event.
- Drafting uses your balance. Usage appears as **Job drafts**. If your balance is empty, Maya can't draft the job, and the form shows a link to top up.
- If Maya can't draft a job, add more detail to your description and try again.

## Create a scheduled job

<Steps>
  <Step title="Open the Jobs panel">
    Go to the agent you want to schedule, then select **Configure** and open the **Jobs** tab.
  </Step>
  <Step title="Start a new job">
    Click **New Job**, then open the **Choose Trigger** tab. To let Maya fill in the form for you, use the **Describe Job** tab instead. See [Draft a job from a description](#draft-a-job-from-a-description).
  </Step>
  <Step title="Pick a trigger">
    Choose a frequency in the **Schedule** section. Then enter a **Name** and describe the **Task** in plain language so the agent knows what to do each run. To start the job from a connected app instead, see [Create an event job](#create-an-event-job).
  </Step>
  <Step title="Set the schedule">
    Select a frequency: **One Time**, **Hourly**, **Daily**, **Weekly**, **Monthly**, or **Custom**.

    - For hourly jobs, you can set a time window and specific minutes past the hour.
    - For daily jobs, you can exclude specific days.
    - The shortest interval allowed is **15 minutes**.
  </Step>
  <Step title="Choose the destination">
    Decide where results go:

    - **New chat for this job** — creates a dedicated chat thread.
    - **An existing chat** — sends results into a chat you already have with the agent.
    - **Job runs only** — stores results without sending them to a chat.
  </Step>
  <Step title="Set the result type">
    Pick whether the agent should produce **a reply in the chat** or **a file, dashboard, or app artifact**. If you choose an artifact, each run must create it; a run without it counts as failed.
  </Step>
  <Step title="Save the job">
    Click **Add Job**. You will see a confirmation that the job was added, and the agent starts if needed.
  </Step>
</Steps>

## Create an event job

An event job runs when something happens in a connected app, for example a new message in a Slack channel. Use it when the agent should react to activity instead of running at fixed times.

<Steps>
  <Step title="Start a new job">
    Open the [Jobs page](https://app.kolmena.ai/jobs) and click **New Job**.
  </Step>
  <Step title="Pick an app">
    On the **Choose Trigger** tab, find the app in the **Integrations** section. You can search triggers by name.
  </Step>
  <Step title="Pick the agent">
    Choose the agent that runs the job. Kolmena asks for the agent first because the app must be attached to that agent.
  </Step>
  <Step title="Connect the app if needed">
    If the app isn't connected, click **Connect**. One click attaches the app to the agent and opens the provider's sign-in window. If you have more than one account for the app, choose it under **Account**.
  </Step>
  <Step title="Choose the event and its settings">
    Select the event under **Trigger**, then fill in its settings. Required settings are marked. For Slack, pick the channel from the channel picker. If an option is not listed, choose **Not in the list?** and paste an ID or link.
  </Step>
  <Step title="Describe the task and save">
    Describe the **Task** in plain language, choose the destination and result type as for a scheduled job, then click **Add Job**.
  </Step>
</Steps>

Each event starts one run. The run appears in the job's run history, and the agent receives the task together with the details of the event.

### Event job behavior and limits

- **Events run in order.** The events of one job run one after another, in the order they arrive.
- **Loop protection.** If a job runs more than 60 times in 10 minutes, Kolmena pauses it and sends you a notice. Check the trigger, then resume the job.
- **Disconnected accounts.** If you disconnect the app account a job uses, Kolmena pauses the job instead of deleting it. Connect the account again, then resume the job.
- **Delayed events.** Some apps are polled rather than pushing events, so an event can arrive 1 to 15 minutes after it happens.
- **No duplicates.** You can't duplicate an event job. Create a new one instead.

<Note>
  Triggers you created in chat before event jobs existed become jobs automatically the next time their event fires.
</Note>

## Create or change a job from chat

You can ask Maya or an agent in chat to create or change a job, including an event job. For example:

```text
When a new message is posted in the #support Slack channel, summarize it and send the summary to this chat.
```

The agent can only create an event job for an app that the job owner has connected. If the app isn't connected, the agent offers the connect step first.

## Edit, pause, or resume a job

You can change a job after it is created. Open the **Jobs** panel, find the job, and click it to edit the name, task, schedule or event, or destination. Click the toggle to pause or resume a job. Paused jobs keep their history but do not run until you turn them back on.

<Warning>
  If a job fails five runs in a row, it automatically stops and shows **Needs attention**. Fix the cause (for example, reconnect an app or choose a valid destination), then click **Resume** to start it again.
</Warning>

## Run a job on demand

To test a schedule or rerun a task immediately, click **Run now** on an active job whose agent is started. The run appears in the job's history right away.

For an event job, **Run now** replays the last event the job received. It is available after the first event arrives.

## View run history

Click **View runs** on any job to open its history. You can see:

| Field | What it shows |
| --- | --- |
| Status | Completed, Failed, Running, Cancelled, or Skipped |
| Trigger | Scheduled or started by an agent |
| Duration | How long the run took |
| Usage | Model calls and tokens consumed |
| Delivered | Whether the result reached its destination |

Select a run to read the agent's transcript and the messages it produced. If the run failed, the error explains why (for example, destination unavailable, agent stopped, or budget exhausted).

## Delete a job

Open the job menu and choose **Delete**. The job and its run history are removed. Any chat created for the job stays in your conversation list.
